\section{What the FOCEX agent does}
% ============================================================
FOCEX obtains the force constants of a crystal (harmonic, cubic, quartic, \dots) by fitting them to
the forces that density-functional theory (DFT) gives on the atoms of a supercell in which every
atom has been displaced a little at random (a \emph{snapshot}). From the force constants it
computes the phonon dispersion, density of states, group velocities, Gr\"uneisen parameters,
elastic constants, sound speeds and the thermal expansion; THERMACOND then computes the lattice
thermal conductivity from the same files.

Making those forces takes many steps: relax the crystal, orient the cell the way FOCEX expects,
compute the Born charges of an insulator, choose a supercell, generate the snapshots, run one DFT
calculation per snapshot, collect the forces, write the five input files of FOCEX and run it. Each
step has its own input files and its own ways to fail. The FOCEX agent, \cmd{focex-agent.py}, does
them all from one short \emph{instruction file}, checks the result of every step, writes what it
did to \cmd{report.log}, and can be restarted at any time: finished steps are not repeated. When a
run stops, \cmd{diagnose.py} finds out where and why, and writes a script that repairs it
(Section~\ref{sec:diagnose}).

It works in one of two modes:

\section{What you need, and how to install it}\label{sec:install}
% ============================================================
You do not need to have used VASP-Flow before: the agent uses it as a library, to write the VASP
input files and the batch scripts. This section has everything you need to set up.

\subsection{The programs}
\noindent\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{0.21\linewidth}>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}p{0.3\linewidth}@{}}
\thead What & Needed for & How to get it \\ \midrule
VASP 5.4 or newer & every DFT step (from\_scratch only) & your licence; on a cluster usually
  a module \\
POTCAR library & VASP: the PAW potentials, one folder per element & comes with VASP \\
MPI & running VASP in parallel (\cmd{mpirun} or \cmd{srun}) & system or cluster module \\
Python $\geq$ 3.8 with numpy, spglib, pymatgen & the agent and \cmd{diagnose.py} & a virtual
  environment, below \\
VASP-Flow & writes the VASP inputs and batch scripts & \cmd{git clone}, below \\
FOCEX, \cmd{read_outcar.x} & the fit; reading the forces from the OUTCARs & this repository,
  \cmd{make focex} \\
SC-SNAPS (\cmd{sc_snaps.x}) & the snapshots (from\_scratch only) & this repository,
  \cmd{make sc_snaps} \\
gnuplot & the plots (PDF) & \cmd{brew install gnuplot}, \cmd{apt install gnuplot}, or a module \\
a Fortran compiler & building FOCEX and SC-SNAPS & \cmd{gfortran} (GCC) \\
\bottomrule
\end{tabularx}

\subsection{Install, once}
The same commands on a workstation and on the login node of a cluster (there, load Python 3.8+
and GCC first, e.g.\ \cmd{module load gcc python}).
\begin{lstlisting}[language=bash]
cd ~
# 1. this repository: FOCEX, its utilities, SC-SNAPS, the agent
git clone https://github.com/KeivanS/Anharmonic-lattice-dynamics.git
cd Anharmonic-lattice-dynamics
make focex sc_snaps     # FOCEX, read_outcar.x, ..., sc_snaps.x -> ~/ALADYN/bin (3 min)
                        # plain "make" also builds THERMACOND (needs MPI) and ANFOMOD
cd ~

# 2. VASP-Flow; the agent imports it from ~/VASP-Flow
#    (another place: export VASP_FLOW_DIR=/that/place)
git clone https://github.com/KeivanS/VASP-Flow.git

# 3. one Python environment for VASP-Flow and the FOCEX agent
python3 -m venv ~/dftphonon-env
source ~/dftphonon-env/bin/activate
pip install numpy spglib pymatgen matplotlib

# 4. optional: the commands focex-agent and focex-diagnose (symlinks in ~/ALADYN/bin)
(cd Anharmonic-lattice-dynamics && make python-tools)
export PATH=~/ALADYN/bin:$PATH     # put this line in ~/.bashrc
\end{lstlisting}
The agent finds the programs at these places; a program installed elsewhere is named in the
instruction file (\cmd{FOCEX_X}, \cmd{SC_SNAPS_X}, \cmd{READ_OUTCAR_X},
Section~\ref{sec:keywords}). With step 4 and the environment active, \cmd{focex-agent} and \cmd{focex-diagnose} are
short for \cmd{python .../FOCEX/AGENT/focex-agent.py} and \cmd{python .../FOCEX/AGENT/diagnose.py}.

\subsection{Tell VASP-Flow where VASP, MPI and the POTCARs are}
\textbf{The POTCAR library} is always given by an environment variable. Put it in your
\cmd{~/.bashrc} (or \cmd{~/.zshrc}) so that every job sees it:
\begin{lstlisting}[language=bash]
export VASP_POTCAR_DIR=/path/to/potpaw_PBE.54     # holds Zn/, O/, Ga/, ...
\end{lstlisting}
\textbf{VASP and MPI} come from a \emph{profile}, a small JSON file in \cmd{~/VASP-Flow/profiles/},
chosen with \opt{profile} (or \cmd{PROFILE:} in the instruction file):

\medskip
\noindent\begin{tabularx}{\linewidth}{@{}>{\ttfamily}p{0.16\linewidth}X@{}}
\thead \normalfont\bfseries profile & \textbf{use it for} \\ \midrule
(none) & a workstation. VASP from the variables \cmd{VASP_STD} (default \cmd{~/BIN/vasp_std})
  and \cmd{MPI_LAUNCH} (default \cmd{mpirun -np}), set in \cmd{~/.bashrc}; the number of ranks is
  \cmd{MPI:} in the instruction file; \cmd{run_workflow.sh} is started with \cmd{bash} \\
workstation & the same, with the paths written in \cmd{profiles/workstation.json} instead \\
slurm & a template for a SLURM cluster: edit \cmd{profiles/slurm.json} (VASP command,
  \cmd{modules} to load, partition, nodes, tasks per node, time, account) \\
\textrm{\emph{your own}} & your cluster: copy \cmd{slurm.json} to \cmd{mycluster.json}, edit it,
  and use \opt{profile mycluster} \\
\bottomrule
\end{tabularx}

\medskip
With a SLURM profile, \cmd{run_workflow.sh} begins with the \cmd{#SBATCH} lines and the
\cmd{module load} lines of the profile and is submitted with \cmd{sbatch}.

\subsection{Check the set-up}
\begin{lstlisting}[language=bash]
source ~/dftphonon-env/bin/activate
python ~/VASP-Flow/check_setup.py local     # a workstation;  "slurm" on a cluster
\end{lstlisting}
It checks Python and its packages, the POTCAR library, VASP and MPI (and on a cluster the
profile), and prints for every problem the command that fixes it. \textbf{Ready.} at the end
means you can start.

\subsection{When is the Python environment needed?}
It is the same environment as in VASP-Flow's manual: one, \cmd{~/dftphonon-env}, serves both (DFT with
VASP-Flow, phonons with the FOCEX agent). It is needed whenever \emph{you} start \cmd{focex-agent.py} or
\cmd{diagnose.py}: they import numpy, spglib,
pymatgen and VASP-Flow. Either activate it first (\cmd{source ~/dftphonon-env/bin/activate}, then
\cmd{python ...}) or call its interpreter directly (\cmd{~/dftphonon-env/bin/python ...}).
The scripts the agent writes (\cmd{run_workflow.sh}, \cmd{resubmit_failed.sh},
\cmd{diagnosis/fix_it.sh}) contain the full path of the interpreter you used, so the batch jobs
need no activation. The plots need only gnuplot; without it the agent writes the plot scripts and
you run \cmd{makeplots.sh} later, where gnuplot is.

\section{Quick start}\label{sec:quick}
% ============================================================
The steps of a from\_scratch calculation (Section~\ref{sec:extract} has those of extract\_only):
\begin{enumerate}
\item \textbf{Make a folder} for the material with its crystal structure, in VASP's POSCAR format,
  named \cmd{POSCAR}. Any cell of the crystal will do -- primitive or not, any orientation: the
  agent reduces and orients it.
\item \textbf{Copy the instruction file} \cmd{FOCEX/AGENT/focex-agent-instructions.txt} into that
  folder and edit it. Only two lines are required: \cmd{Project:} (a name) and \cmd{RANKS:} (which
  force constants to fit, e.g.\ \cmd{1 1 1 0 0 0 0 0} for harmonic and cubic). Set also
  \cmd{FUNCTIONAL:} and \cmd{MPI:} (the number of MPI ranks for VASP); every other line is
  optional and shows its default.

  \textbf{Where the calculations go} is also set in this file, by \cmd{PROJECT_DIR:}: a path
  relative to the folder of the instruction file (\cmd{PROJECT_DIR: runs/ZnO_PBEsol}) or absolute
  (\cmd{PROJECT_DIR: /scratch/me/ZnO}, \cmd{~} allowed). Without it the project folder is a folder
  named after \cmd{Project:} next to the instruction file. The agent creates it, with any missing
  parent folders; if it holds a project already, the agent stops unless \opt{force} is given.
\item \textbf{Set up the project}: the agent creates the project folder with the relaxation inputs
  and \cmd{run_workflow.sh}, and prints the command to start it. This takes seconds and runs no
  VASP.
\item \textbf{Start the workflow} from the project folder, and follow \cmd{report.log}.
\item \textbf{If it stops}, run \cmd{diagnose.py} (Section~\ref{sec:diagnose}).
\end{enumerate}
\begin{lstlisting}[language=bash]
cd ~/work/ZnO                      # holds POSCAR
A=~/Anharmonic-lattice-dynamics/FOCEX/AGENT
cp $A/focex-agent-instructions.txt .
nano focex-agent-instructions.txt  # Project, RANKS, FUNCTIONAL, MPI

source ~/dftphonon-env/bin/activate
python $A/focex-agent.py --profile mycluster   # your profile (above)
cd ZnO
sbatch run_workflow.sh             # without a profile: nohup bash run_workflow.sh &
tail -f report.log
\end{lstlisting}
The options of \cmd{focex-agent.py} are all optional:

\medskip
\noindent\begin{tabularx}{\linewidth}{@{}>{\ttfamily}p{0.22\linewidth}X@{}}
\thead \normalfont\bfseries option & \textbf{meaning} \\ \midrule
-{}-instr FILE & the instruction file, if it is not called \cmd{focex-agent-instructions.txt} \\
-{}-coord FILE & the crystal structure, if it is not called \cmd{POSCAR} (from\_scratch) \\
-{}-profile NAME & the VASP-Flow profile (previous section); default: \cmd{PROFILE:} of the
  instruction file, else none \\
-{}-force & set up again a project folder that exists already. Its record of finished tasks is
  reset, so use it only to start over, after removing the old run folders \\
\bottomrule
\end{tabularx}

\begin{notebox}
\textbf{Threads.} You do not have to do anything about OpenMP threads: the agent runs VASP with one
thread per MPI rank (\cmd{OMP_NUM_THREADS=1}). Without that, a BLAS library built with OpenMP
starts one thread per core in every MPI rank and the cores are oversubscribed many times (a
96-atom ZnO supercell made no SCF step in 30 minutes on 8 ranks). Only if your VASP is built for
hybrid MPI\,+\,OpenMP runs and you want them, set \cmd{VASP_OMP_NUM_THREADS} to the number of
threads per rank before you start the workflow.
\end{notebox}

\section{Mode from\_scratch: from a POSCAR to phonons}\label{sec:scratch}
% ============================================================
\cmd{run_workflow.sh} runs \cmd{focex-agent.py run <PROJECT_DIR>}, which does the eleven tasks below
in order. Each finished task is recorded in \cmd{state.json} and in \cmd{report.log}, with what was
checked; a task that fails stops the workflow, and starting \cmd{run_workflow.sh} again continues
from that task. A job that hits its time limit is simply submitted again.

The supercell tasks are checked again before they are skipped:
\begin{itemize}
\item \textbf{A removed or incomplete \cmd{04_supercells/snap_NNN} folder} is written again, and the
  \cmd{supercells} task and every task after it are redone. Only the folders without a converged
  OUTCAR run VASP.
\item \textbf{To leave snapshots out on purpose}, move their folders to \cmd{04_supercells/unused/}.
  They are then not recreated, and \cmd{FORCEDISP1} is collected again from the others.
\item \textbf{A \cmd{snap_NNN} folder with no \cmd{03_snaps/poscar_NNN}} stops the workflow.
\item \textbf{To add snapshots}, raise SNAPSHOTS in the project's \cmd{focex-agent-instructions.txt}
  and start \cmd{run_workflow.sh} again. The extra snapshots are made at the same temperature and
  numbered after the existing ones, which are kept; only the new ones run VASP, then FOCEX is run
  again on all of them. A lower SNAPSHOTS removes nothing.
\end{itemize}

\begin{description}
\item[relax] The structure you gave is reduced to its primitive cell (Niggli reduction) and rotated
  into the orientation FOCEX and SC-SNAPS use (Section~\ref{sec:frame}); the result is
  \cmd{POSCAR.init}. VASP relaxes the atoms and the cell shape and volume in \cmd{01_relax}. If the
  forces are not yet below EDIFFG after NSW ionic steps, the relaxation continues from its last
  structure (CONTCAR), up to three times.
\item[poscar0] The relaxed cell is reduced and oriented again and written as \cmd{POSCAR0}: every
  later step uses this cell and this Cartesian frame. The report gives its space group and lattice
  parameters.
\item[scf] A self-consistent calculation on POSCAR0 in \cmd{02_scf} (same INCAR, no ionic steps,
  same k-mesh), which also gives the band gap. If the cell did not change in the previous task, it
  starts from the charge density and wave functions of the relaxation.
\item[dfpt] For an insulator (band gap above 0.05\,eV, \cmd{DFPT: auto}): density-functional
  perturbation theory in \cmd{02_scf/dfpt} gives the high-frequency dielectric constant and the
  Born effective charges of every atom (Section~\ref{sec:born}). \cmd{DFPT: on} forces it,
  \cmd{off} skips it.
\item[snaps] The supercell is chosen (Section~\ref{sec:supercell}). SC-SNAPS
  (\cmd{03_snaps}) then writes the undistorted supercell \cmd{poscar_000} and 50 snapshots, each
  atom displaced as in a thermal ensemble of harmonic oscillators of frequency \cmd{AVG_FREQ} at
  temperature \cmd{TEMPERATURE}. \textbf{A temperature you give is used as it is}, e.g.\ to
  sample the displacements of that temperature for effective phonons; the report gives the
  resulting rms displacement. Only when \cmd{TEMPERATURE} is not given, the default 30\,K is
  adjusted (SC-SNAPS rerun at most twice) until the rms displacement is within 15\,\% of
  \cmd{DISP_TARGET} (0.02\,\AA): large enough for clean forces, small enough for the Taylor
  expansion of the energy. The undistorted supercell is
  checked to be an exact multiple of POSCAR0 before any VASP job is run.
\item[supercells] One folder per snapshot, \cmd{04_supercells/snap_NNN}, with its POSCAR, the SCF
  INCAR without symmetry (\cmd{ISYM = 0}) and a k-mesh equivalent to the SCF one
  (Section~\ref{sec:kmesh}); magnetic moments given per atom are carried over to the supercell.
\item[vasp\_snaps] The VASP runs of the snapshots, one after the other. A run that fails does not
  stop the others; the failed ones are listed in \cmd{report.log}, and \cmd{resubmit_failed.sh}
  reruns only those. An existing OUTCAR is never overwritten (it is kept as \cmd{OUTCAR.1}, \dots).
\item[collect] \cmd{read_outcar.x} reads the positions and forces of every run into
  \cmd{04_supercells/FORCEDISP1}; \cmd{POSCAR1} is the undistorted supercell. The report gives the
  largest net force on a supercell (should be $\approx 0$) and the largest difference between the
  positions in OUTCAR and in POSCAR. The undistorted supercell (\cmd{snap_000}, run with
  \cmd{ISIF = 2}; the other snapshots use \cmd{ISIF = 1}, which gives only the trace) also gives the
  stress of the reference structure: \cmd{stress.params} (GPa, tensile positive, i.e.\ minus the
  \cmd{in kB} line of OUTCAR divided by 10) is written and copied to the FOCEX folders, where it
  enters the Huang rows and the elastic constants.
\item[focex] The five input files of FOCEX are written in \cmd{05_focex} (\cmd{structure.params},
  \cmd{latdyn.params}, \cmd{kpbs.params}, \cmd{dielectric.params}, \cmd{default.params}) and FOCEX
  is run. With Born charges a second run without them is made in \cmd{05_focex/NOBORN}, for
  comparison; with fewer than \cmd{LASSO_RATIO} (2) equations per unknown, a third run with LASSO,
  which keeps only the force constants the data need, is made in \cmd{05_focex/LASSO}. The report
  gives the fit error, the numbers of equations and unknowns, the lowest $\omega^2$ (a warning
  below $-25$\,cm$^{-2}$: imaginary modes) and the highest frequency. If the DOS range of
  \cmd{latdyn.params} does not fit the frequencies, FOCEX is run again with one that does.
\item[plots] The gnuplot scripts \cmd{bvel.plt}, \cmd{all.plt}, \cmd{qha.plt} are filled in and run
  in every FOCEX folder (Section~\ref{sec:results}); \cmd{makeplots.sh} remakes them.
\item[thermacond] THERMACOND in \cmd{06_thermacond}: linewidths or the thermal conductivity, when
  \cmd{THERMACOND_JOB} is 1, 2 or 3; skipped for 0, the default (Section~\ref{sec:thermacond}).
\end{description}

\subsection{Defaults}
\begin{itemize}
\item \cmd{ACCURACY: Accurate}: ENCUT 600\,eV, EDIFF $10^{-7}$\,eV, EDIFFG $-0.001$\,eV/\AA,
  PREC Accurate in every VASP step. \cmd{Normal}: 450\,eV, $10^{-6}$, $-0.003$, PREC Normal --
  cheaper, but the residual forces of the relaxed structure are larger (0.01\,eV/\AA\ in a ZnO
  test), which adds noise to the force constants. DFPT uses EDIFF $10^{-8}$.
\item Relaxation and SCF k-mesh: VASP-Flow's \cmd{coarse} density (1000 k-points per reciprocal
  atom), \cmd{fine} (6000) if every element is a metal. Each subdivision is rounded to the nearest
  integer; VASP-Flow itself rounds to even numbers (multiples of 6 in plane for hexagonal cells), the
  agent does not. The FOCEX mesh (\cmd{FOCEX_MESH}) is made the same way.
\item 50 snapshots. Each gives three equations per atom of the supercell: 20 snapshots of a
  96-atom supercell give 5760 equations for the 264 unknowns of ZnO with ranks 1--3, so fewer
  snapshots are often enough (\cmd{SNAPSHOTS}).
\item \cmd{RANGE: 6 2 1 0 0 0 0}: neighbour shells kept for ranks 2, 3, 4, \dots;
  \cmd{FC2RANGE: 0}: the harmonic force constants are kept over the whole supercell.
\item FOCEX k-mesh \cmd{fine}; the band-structure path is found automatically.
\end{itemize}

\subsection{The supercell}\label{sec:supercell}
\cmd{SUPERCELL:} takes one of three forms:
\begin{itemize}
\item \cmd{SMALL} (the default): the multiple $m_1\times m_2\times m_3$ of the conventional cell
  with the fewest atoms whose faces are at least 10\,\AA\ apart, at most 100 atoms;
\item \cmd{LARGE}: the same with 14\,\AA\ and at most 300 atoms. In both, if no such multiple is
  small enough, the one with the largest face distance; it keeps the symmetry of the lattice;
\item \textbf{the supercell matrix itself}: nine integers, the three rows of the matrix that the
  agent writes to SC-SNAPS's \cmd{supercell.inp}. The first three integers $n_{11}\,n_{12}\,n_{13}$
  give the first supercell vector as a combination of the primitive vectors of POSCAR0,
  $\mathbf R_{S1} = n_{11}\mathbf R_{01} + n_{12}\mathbf R_{02} + n_{13}\mathbf R_{03}$; the next three
  give $\mathbf R_{S2}$ and the last three $\mathbf R_{S3}$ in the same way (the agent's
  \cmd{cell.inp} has \cmd{convcoord = 1}, primitive units). For example
  \cmd{SUPERCELL: 2 0 0  0 2 0  0 0 2} is $2\times2\times2$ primitive cells, and for an fcc
  crystal \cmd{SUPERCELL: -1 1 1  1 -1 1  1 1 -1} is its conventional cube (4 primitive cells).
  The determinant must be positive.
\end{itemize}
The report gives the matrix and the number of atoms (for SMALL and LARGE also the face distance). Prefer supercells that keep the symmetry of the lattice: with a supercell that does
not (for example $4\times3\times2$ of a hexagonal cell), FOCEX can stop with
\cmd{R+tp-t not inside!} (Section~\ref{sec:diagnose}).

\subsection{The FOCEX frame}\label{sec:frame}
FOCEX and SC-SNAPS build the conventional cell from $a, b, c, \alpha, \beta, \gamma$ with $a$ along
$x$ and $b$ in the $xy$ plane, and the supercells, forces and Born charges must be in that same
Cartesian frame. The agent rotates the cell into it at the start, so everything VASP computes is
already in the right frame. \cmd{structure.params} lists the conventional cell (line 1), the
primitive vectors in its units (line 2) and the atoms in conventional coordinates.

\subsection{The k-mesh of the supercells}\label{sec:kmesh}
If the supercell is a diagonal multiple of the primitive cell, its mesh is the SCF mesh divided by
the multiples, rounded up (6\,6\,4 with a $3\times3\times2$ supercell gives 2\,2\,2). Otherwise
(every multiple of a centred conventional cell) it keeps the k-point spacing of the SCF mesh.
\cmd{KPOINTS_snaps} sets it yourself (Section~\ref{sec:override}).

% ============================================================
\section{Mode extract\_only: FOCEX on existing data}\label{sec:extract}
% ============================================================
Use it when the supercell forces exist already -- from an earlier calculation, another code, or a
colleague -- and you want FOCEX's force constants and phonons. No VASP and no SC-SNAPS are run.

\paragraph{The data folder} (named in the instruction file with \cmd{DATA:}) holds
\begin{itemize}
\item \cmd{POSCAR1} and \cmd{FORCEDISP1}: a supercell and the positions and forces of its
  snapshots, in FOCEX's format (what \cmd{read_outcar.x} or \cmd{read_qe.x} write); more pairs
  \cmd{POSCAR2}/\cmd{FORCEDISP2}, \dots\ are all used. Any orientation.
\item optionally \cmd{POSCAR}: the primitive cell, in the same orientation as the data; without it,
  spglib finds the primitive cell of \cmd{POSCAR1}.
\item optionally \cmd{dielectric.params}: the dielectric constant and the Born charges, in the
  frame of the data, one $3\times3$ block per atom of that primitive cell. With more than one atom
  of a species the primitive \cmd{POSCAR} is required, to fix the order of the atoms.
\end{itemize}
\cmd{SPECIES: Mg O} names the elements when the POSCARs have no element line.

\paragraph{What the agent does.} At set-up it symmetrizes the lattice of the primitive cell (DFT
lattice parameters given to 6--7 digits make FOCEX's symmetry analysis lose force constants),
finds the rotation into the FOCEX frame, and rotates the supercells, the positions and forces in
\cmd{FORCEDISPi}, the dielectric constant and the Born charges with it. The report gives the
rotation and the size of the symmetrization. The workflow then has only the tasks focex and plots.
\begin{lstlisting}[language=bash]
cat > focex-agent-instructions.txt <<'EOF'
Project: MgO
MODE: extract_only
DATA: ~/data/MgO_forces          # POSCAR1, FORCEDISP1, dielectric.params
SPECIES: Mg O
RANKS: 1 1 1 0 0 0 0 0
EOF
python ~/Anharmonic-lattice-dynamics/FOCEX/AGENT/focex-agent.py
cd MgO && bash run_workflow.sh          # FOCEX takes minutes: no batch job needed
\end{lstlisting}
Checked on MgO data given in a rhombohedral orientation: the fit error (7.197\,\%), the 35
unknowns, the frequencies and the elastic moduli are those of a FOCEX run in the original frame.

\section{Changing the files the agent writes}\label{sec:override}
% ============================================================
Every file the agent generates can be changed \emph{from the instruction file}, with a block named
after the file: a line with its name, the contents, and a line with the name followed by
\cmd{_END}.
\begin{itemize}
\item \textbf{INCAR blocks are merged tag by tag}: the tags you give replace or add to those the
  agent writes; the others stay. \cmd{INCAR} applies to every VASP step; \cmd{INCAR_relax},
  \cmd{INCAR_scf}, \cmd{INCAR_dfpt}, \cmd{INCAR_snaps} to one.
\item \textbf{Every other block replaces the whole file}, so it must be complete: \cmd{KPOINTS}
  (relaxation and SCF), \cmd{KPOINTS_snaps}, \cmd{cell_inp}, \cmd{supercell_inp}, \cmd{snaps_inp}
  (SC-SNAPS), \cmd{structure_params}, \cmd{latdyn_params}, \cmd{kpbs_params},
  \cmd{dielectric_params}, \cmd{default_params} (FOCEX).
\end{itemize}
Simple choices -- the supercell, the number of snapshots, the FOCEX k-mesh -- have their own
keyword; use a block only for what has none.

\paragraph{Example.} Wurtzite ZnO without Hubbard U (VASP-Flow would otherwise put its tabulated U
on Zn, an oxide), \cmd{LASPH} in every VASP step, stricter electronic convergence only in the
supercell runs, a $3\times3\times2$ supercell, 20 snapshots, a denser FOCEX mesh, and your own band
path $\Gamma$--M--K--$\Gamma$--A, which replaces \cmd{kpbs.params}:
\begin{lstlisting}
Project: ZnO
RANKS: 1 1 1 0 0 0 0 0
FUNCTIONAL: PBEsol
GGA_U: OFF
MPI: 40
SUPERCELL: 3 0 0  0 3 0  0 0 2       # rows: supercell vectors in primitive units
SNAPSHOTS: 20
FOCEX_MESH: 12 12 8
KPATH: 1                              # the band path is given below

INCAR                                 # every VASP step (merged tag by tag)
  LASPH = .TRUE.
INCAR_END
INCAR_snaps                           # the supercell runs only
  NELM = 200
  ALGO = All
INCAR_snaps_END
kpbs_params                           # replaces kpbs.params (FOCEX's band path)
1        # coordinates in units of the primitive reciprocal vectors
60       # k-points per segment
4        # number of segments
G   0.000000 0.000000 0.000000
M   0.500000 0.000000 0.000000
K   0.333333 0.333333 0.000000
G   0.000000 0.000000 0.000000
A   0.000000 0.000000 0.500000
kpbs_params_END
\end{lstlisting}
After the set-up you can read \cmd{01_relax/INCAR} before anything runs.

\section{Born charges and the dielectric constant}\label{sec:born}
% ============================================================
In an insulator, the long-range Coulomb interaction between the displaced ions splits the
longitudinal and transverse optical modes near $\Gamma$ (LO--TO splitting). FOCEX includes it
with the Born effective charges $Z^*$ and the high-frequency dielectric constant
$\varepsilon_\infty$; without them the optical branches near $\Gamma$ are wrong.
\begin{itemize}
\item from\_scratch: the agent computes them (task dfpt) when the SCF shows a band gap, writes them
  to \cmd{dielectric.params}, and makes for comparison a FOCEX run without them in
  \cmd{05_focex/NOBORN}. \cmd{DFPT: off} skips them; \cmd{on} computes them for any material.
\item extract\_only: give them in \cmd{dielectric.params} in the data folder.
\item your own values, in either mode: a \cmd{dielectric_params} block (it replaces the file).
\end{itemize}
\begin{notebox}
VASP prints $Z^*_{ij}$ with $i$ the direction of the field and $j$ that of the displacement;
FOCEX expects the transpose, which the agent writes. \cmd{BORN_TRANSPOSE: no} writes them as VASP
prints them; you should not need it.
\end{notebox}

\section{When a run stops: diagnose.py}\label{sec:diagnose}
% ============================================================
\begin{lstlisting}[language=bash]
A=~/Anharmonic-lattice-dynamics/FOCEX/AGENT
python $A/diagnose.py ~/work/ZnO/ZnO     # one or more project folders
less ~/work/ZnO/ZnO/diagnosis/report.txt
bash ~/work/ZnO/ZnO/diagnosis/fix_it.sh
\end{lstlisting}
\cmd{diagnose.py} itself changes nothing. It lists every task as done, FAILED, INTERRUPTED (the
job was killed inside it) or not reached, or reports that the project is still running or not yet
started. For a failed task it finds the cause from \cmd{report.log}, the OUTCARs, \cmd{vasp.out},
\cmd{focex.out} and the SLURM logs, and writes \cmd{diagnosis/report.txt} (what failed, where, the
evidence, what the fix will change) and \cmd{diagnosis/fix_it.sh}. VASP failures are recognised
with the rules of VASP-Flow's diagnosis tool; FOCEX, SC-SNAPS and \cmd{read_outcar.x} stops by
their messages.

\medskip
\noindent\begin{tabularx}{\linewidth}{@{}>{\ttfamily\raggedright\arraybackslash}p{0.2\linewidth}>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X@{}}
\thead \normalfont\bfseries cause & \textbf{meaning} & \textbf{what fix\_it.sh does} \\ \midrule
timeout & the job hit its time limit & walltime $\times 2$, resubmit \\
scf\_nelm & SCF not converged in NELM steps & ALGO = All, NELM = 200 \\
edddav & the Davidson eigensolver failed & ALGO = All \\
zbrent & the relaxation's line search failed & IBRION = 1 \\
relax\_unconv & relaxation not converged & resubmit (continues from CONTCAR) \\
oom & out of memory & KPAR = 1 \\
mpi\_init, not\_run, interrupted & MPI did not start; never ran; killed & resubmit \\
ws\_outside & FOCEX \cmd{R+tp-t not inside!}: the supercell lacks the symmetry of the lattice &
  held: choose another supercell, redo from the snapshots \\
others & disk quota, symmetry, an unknown stop, \dots & held, with the error lines \\
\bottomrule
\end{tabularx}

\medskip
New INCAR tags go into the INCARs of the failed runs and into the matching block of the project's
instruction file (\cmd{INCAR_snaps}, \dots), so that later runs use them too. Before it changes
anything, \cmd{fix_it.sh} checks that nothing is running and that nothing changed since the
diagnosis, and copies every file it edits to \cmd{diagnosis/backup_<date>/}; then it resubmits
(\cmd{sbatch} with a SLURM profile, otherwise \cmd{bash} in the background). When the fix needs
your judgement -- a cause it does not know, a fix that was already tried, a new supercell -- the
script is \emph{held}: it prints what to do and stops, and \cmd{bash fix_it.sh --anyway} runs its
suggested commands as they are. Run \cmd{diagnose.py} again when the resubmitted job has finished.

\begin{tipbox}
ZnO with a $4\times3\times2$ supercell: \emph{task focex, 05\_focex: ws\_outside -- an FC2 pair of
a kept symmetry group lies outside the Wigner-Seitz cell of the supercell \dots; evidence:
focex.out: "SET\_DYNMAT\_STD: R+tp-t not inside!"; HELD for review: use a supercell with the
symmetry of the lattice, then redo from the snapshots.}
\end{tipbox}

\section{Thermal conductivity}\label{sec:thermacond}
% ============================================================
The last task, \cmd{thermacond}, runs THERMACOND on the force constants of \cmd{05_focex}. Whether
it runs is decided by the THERMACOND job, line 8 of \cmd{latdyn.params}, which you set in the
instruction file:

\medskip
\noindent\begin{tabularx}{\linewidth}{@{}>{\ttfamily}p{0.31\linewidth}X@{}}
\thead \normalfont\bfseries THERMACOND\_JOB & \textbf{what THERMACOND does} \\ \midrule
0 (default) & nothing: the task is skipped (FOCEX has already given the bands, DOS and Gr\"uneisen
  parameters) \\
1 & three-phonon linewidths of every mode along the band path (\cmd{lw-selfenergy.dat}) \\
2 & thermal conductivity: RTA and the direct solution of the BTE \\
3 & thermal conductivity: RTA and the iterative solution of the BTE \\
\bottomrule
\end{tabularx}

\medskip
\begin{lstlisting}
RANKS: 1 1 1 0 0 0 0 0        # cubic force constants are needed
THERMACOND_JOB: 2
THERMACOND_MESH: 12 12 12     # latdyn.params line 1 for THERMACOND (default: the FOCEX mesh)
THERMACOND_T: 100 900 9       # line 6: Tmin, Tmax (K), number of temperatures
# THERMACOND_SOLVER: 0        # line 9, job 2: 0 conjugate gradient, 1 SVD
\end{lstlisting}
The task copies \cmd{lat_fc.dat}, \cmd{fc2.dat}, \cmd{fc3.dat}, \cmd{structure.params},
\cmd{dielectric.params} and \cmd{kpbs.params} from \cmd{05_focex} to \cmd{06_thermacond}, writes
there FOCEX's \cmd{latdyn.params} with lines 1, 6, 8 and 9 from these keywords, and runs
\cmd{tcond-2.0.x} with the MPI command of the profile; \cmd{05_focex} is not changed. A
\cmd{latdyn_params} block (Section~\ref{sec:override}) sets all 13 lines for both FOCEX and
THERMACOND, and its line 8 is the job unless \cmd{THERMACOND_JOB} is given. The mesh is the
expensive choice: the FOCEX default (\cmd{fine}) is usually far too dense, so set
\cmd{THERMACOND_MESH} and converge \cmd{kappa} with it.

The report gives, at up to seven of the temperatures, $\kappa_{RTA}$, the full (direct or iterative)
solution and the coherences term $\kappa_C$ of the Wigner formulation (W/mK, average of the
diagonal), and a warning if the full solution falls below the RTA, which it should not do (the
direct solver has an open issue: compare with job~3). The complete results are in
\cmd{06_thermacond}: \cmd{kappa_vs_T.dat}, \cmd{kappa_wigner.dat}, \cmd{Qvalue.dat} (scattering
rates) and the other files described in the THERMACOND manual. An existing project gets the task
by adding \cmd{THERMACOND_JOB} to its \cmd{focex-agent-instructions.txt} and submitting
\cmd{run_workflow.sh} again: the finished tasks are skipped.
